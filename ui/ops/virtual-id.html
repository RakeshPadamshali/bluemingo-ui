Virtual ID Register & reconciliation

Production continues when a billet is physically present but its batch id is not yet in the system: a super-user creates a virtual id (the heat's planned number when known), the material charges and rolls normally, Level 2 receives the virtual number; when the actual id arrives an authorised user reconciles (SAP postings: deferred — PPC outbox).
Prototype on sample data — every control works; a reload resets. Try: as Super-user, Reconcile V-2627-01172-07 (B031142 arrived) — first pick the B031148 decoy (another heat, refused) · Missing-number check on heat 2627-01173 → create V-2627-01173-08 for B031146 · a known heat with no gap (2627-01171) is refused as a duplicate · Confirm production under the virtual id (postings held) → Simulate batch arrival → Reconcile (postings released) · Level 2 offline → create → Push / back online · +1 day twice → overdue alert · Cancel / scrap · filter by status · the charging operator is refused the privileged steps.
